# Web Frontend

Applies when: Any project with a browser frontend, whatever the UI framework.

Read a rule file only when the rule may apply. The file of rule `<rule-id>` is `rules/<rule-id>.md`.

- `batch-dom-reads-writes` [medium] Group DOM layout reads together and style writes together, or toggle a CSS class, so the browser does not run a forced reflow after every write. When: Code sets styles or classes on elements and reads layout values, such as `offsetWidth`, `getBoundingClientRect` or `getComputedStyle`, in the same function or loop.
- `bundle-analyzable-paths` [low] Import modules through literal paths or an explicit map of loaders, so the bundler can see the full set of reachable files. When: Code builds a module path or file path from a variable, for dynamic import or build-time file access.
- `bundle-barrel-imports` [low] Import from the specific module when a barrel file re-exports many modules and the toolchain cannot drop the unused ones, such as dev servers, tests, CommonJS packages or packages with side effects. When: Code imports from a barrel file (an index that re-exports many modules), from a package or from the project's own source.
- `bundle-conditional` [low] Load heavy modules or data with dynamic import when the user turns the feature on, instead of in the initial bundle. When: A large module or data file is used only behind a toggle, a route, a tab or another user action.
- `bundle-defer-third-party` [low] Load analytics, logging and error tracking scripts after first render or at idle time, so they do not compete with the code that makes the page usable. When: The frontend loads analytics, tracking, chat widgets, error reporting or similar third-party code that the first interaction does not need.
- `bundle-preload` [low] Start loading a heavy lazy module when the user shows intent, such as hover or focus on its trigger, or when a feature flag turns it on. When: A heavy module loads lazily on a user action, and a visible wait follows the action.
- `client-localstorage-schema` [medium] Put a version in each `localStorage` key, store only the fields the UI needs, and wrap every storage call in `try`/`catch`. When: Code reads or writes `localStorage` or `sessionStorage`.
- `client-passive-event-listeners` [low] Pass `{ passive: true }` to `touchstart`, `touchmove` and `wheel` listeners on elements when they never call `preventDefault`, so scrolling does not wait for the handler. When: Code adds `touchstart`, `touchmove` or `wheel` listeners with `addEventListener`, on an element other than `window`, `document`, `document.documentElement` or `body`.
- `defer-work-to-idle` [low] Schedule analytics, cache writes and prefetching with `requestIdleCallback`, and fall back to `setTimeout` where it is missing, such as in Safari. When: An event handler or startup path runs work that the user does not wait for, such as analytics, storage writes, prefetching or background processing.
- `rendering-content-visibility` [low] Apply `content-visibility: auto` with `contain-intrinsic-size` to repeated blocks in long scrolling pages, so the browser skips layout and paint for the ones off screen. When: A page renders hundreds of similar blocks, such as list items, feed cards or article sections, and most are off screen at load.
- `rendering-script-defer-async` [medium] Mark external `<script>` tags in HTML with `defer` or `async`, so the download does not block HTML parsing. When: HTML, a template or a layout component outputs a `<script>` tag with a `src` attribute.
- `rendering-svg-precision` [low] Round SVG path coordinates to the precision the viewBox needs, usually one or two decimals, with an optimizer such as SVGO. When: The project adds SVG files or inline SVG paths, especially icons exported from a design tool.
