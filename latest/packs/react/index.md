# React Best Practices

Applies when: Any project that uses React.

Read a rule file only when the rule may apply. The file of rule `<rule-id>` is `rules/<rule-id>.md`.

- `advanced-effect-event-deps` [low] Leave functions from `useEffectEvent` out of effect dependency arrays. List only the reactive values the effect reads, and call the Effect Event inside the effect. When: Code that calls `useEffectEvent` (React 19.2 or later) and passes the result to `useEffect`, `useLayoutEffect` or `useInsertionEffect`.
- `advanced-event-handler-refs` [low] When an effect must not re-run on every callback change, read the callback through `useEffectEvent` (React 19.2+). On older React, store it in a ref. When: An effect subscribes to an external source or starts a timer and calls a callback prop or handler that changes on each render.
- `advanced-init-once` [low] Run app-wide setup that must happen once per page load at module level in the entry module, not in a component effect with an empty dependency array. When: A component effect with an empty dependency array runs app-wide setup such as loading stored state, checking a token or configuring an SDK.
- `async-suspense-boundaries` [medium] Do not await data at the top of a page component. Move the wait into the component that needs the data and wrap it in `Suspense`, so the rest of the page renders first. When: Async Server Components, or components that read promises with `use()` or a Suspense-enabled data library, where a wait blocks a whole page or layout.
- `bundle-dynamic-imports` [medium] Load large components, such as editors, charts or maps, on demand with a dynamic import, so they stay out of the initial bundle. When: A component with a large dependency is imported statically but is hidden, below the fold, behind an interaction, or on a secondary route.
- `rendering-activity` [low] For expensive UI that users toggle often, wrap it in `<Activity>` with `mode` `"visible"` or `"hidden"` to keep its state and DOM, instead of unmounting and re-creating it. When: A component with costly render or local state is mounted and unmounted by a condition that users toggle often, such as tabs, panels or menus. Needs React 19.2 or later.
- `rendering-conditional-render` [medium] Use a ternary or a boolean comparison for conditional JSX when the condition can be `0` or `NaN`. The `&&` operator renders those values as text. When: JSX uses `condition && element` where the condition is a number, such as a count or length, or any value that can be `0` or `NaN`.
- `rendering-hoist-jsx` [low] Move large JSX that never changes, such as big SVGs, to a module-level constant, unless React Compiler is enabled. When: A component creates a large JSX element or SVG that has no props or state, and the project does not use React Compiler.
- `rendering-hydration-no-flicker` [medium] For values only the browser knows, such as a stored theme, set them with a small blocking inline script before first paint. Do not read storage in render or fix it in an effect. When: Server-rendered pages whose first paint depends on browser-only data such as `localStorage`, a cookie that the server cannot read, or a media query.
- `rendering-hydration-suppress-warning` [low] Add `suppressHydrationWarning` to one small element when its content differs between server and client by design, such as a timestamp. Do not use it to hide real mismatches. When: Server-rendered React code renders values that differ between server and client by design, such as the current time, locale or time zone formatting, or random values.
- `rendering-resource-hints` [low] Call `prefetchDNS`, `preconnect`, `preload` or `preinit` during render for fonts, stylesheets and origins that the page will need, so the browser starts early. Needs React 19 or later. When: A server-rendered page, or code that knows ahead that it needs a font, stylesheet, script, module or third-party origin, in a project on React 19 or later.
- `rendering-usetransition-loading` [low] Use `useTransition` and its `isPending` flag for loading state of an async update, instead of a manual `useState` boolean that you set before and after the work. When: An event handler sets a loading boolean to true, awaits async work, then sets it to false, and the result updates state.
- `rerender-defer-reads` [low] Do not subscribe to changing state, such as URL search params, when the value is only read inside a callback. Read it on demand in the callback. When: Components that call a hook subscribing to changing external state but only use the value in event handlers or callbacks.
- `rerender-dependencies` [low] List primitive values in effect dependency arrays instead of objects, and compute derived booleans outside the effect, so the effect re-runs only when the used value changes. When: Effects, memos or callbacks whose dependency array holds an object or a fast-changing value that the body reduces to a smaller one.
- `rerender-derived-state` [low] Subscribe to a derived boolean or small value instead of a continuously changing value, so the component re-renders only when the result changes. When: Components that read a fast-changing value, such as window width or scroll position, and only use a coarse result of it.
- `rerender-derived-state-no-effect` [medium] Do not store a value in state, or sync it in an effect, when it can be computed from props or state. Compute it during render, or reset state with a key. When: Components that call a state setter inside an effect to mirror or transform props or other state.
- `rerender-functional-setstate` [medium] When the next state depends on the current state, pass an updater function to the setter instead of reading the state variable. This avoids stale closures and extra dependencies. When: State setters called with a value built from the same state variable, especially inside `useCallback`, effects, timers or async code.
- `rerender-lazy-state-init` [low] Pass a function to `useState` when the initial value is costly to compute, so the work runs once instead of on every render. When: `useState` or `useReducer` calls whose initial value comes from a function call that parses, builds or reads data, such as `localStorage`, indexes or maps.
- `rerender-memo` [low] Move costly computation into a memoized child component, so the parent can return early, for example while loading, without doing the work. When: Components that compute a costly value with `useMemo` before an early return, or re-render often with props that rarely change.
- `rerender-memo-with-default-value` [low] Give optional object, array or function props of a memoized component a module-level constant as default, not an inline literal, so memo comparison keeps working. When: Components wrapped in `memo` whose destructured props have a default value that is an object, array or function.
- `rerender-move-effect-to-event` [medium] Run side effects caused by a user action in the event handler. Do not model the action as state and react to it in an effect. When: Components that set a flag in a handler and then run a side effect, such as a request or toast, in an effect that watches the flag.
- `rerender-no-inline-components` [high] Declare components at module level and pass data as props. A component defined inside another component is a new type on each render, so React remounts it. When: Component functions or arrow functions declared inside the body of another component and used as JSX elements.
- `rerender-simple-expression-in-memo` [low] Do not wrap a cheap expression that returns a boolean, number or string in `useMemo`. The hook and its dependency check can cost more than the expression. When: `useMemo` calls whose body is a short logical or arithmetic expression with a primitive result.
- `rerender-split-combined-hooks` [low] Split a `useMemo` or `useEffect` that does several independent tasks into one hook per task, so each task re-runs only when its own dependencies change. When: `useMemo`, `useCallback` or `useEffect` hooks with a long dependency array whose steps use different subsets of the dependencies.
- `rerender-transitions` [low] Wrap state updates that trigger a costly or blocking render, and are not urgent, in `startTransition` or `useTransition` so urgent input stays responsive. When: State updates that cause a heavy re-render, such as switching a tab, filtering a large list or navigating a view, next to urgent updates like typing or clicking.
- `rerender-use-deferred-value` [low] When typing or another input drives a costly render, pass a deferred copy of the value to the costly part so the input stays responsive. When: A controlled input value filters a large list or feeds a costly chart or view in the same render as the input.
- `rerender-use-ref-transient-values` [low] Store values that change often and do not affect the rendered output, such as pointer position or timer ids, in a ref instead of state. Update the DOM directly when needed. When: State updated from high-frequency events, such as `mousemove`, `scroll` or intervals, where each update only moves an element or feeds a later callback.
- `reset-overlay-state-on-open` [medium] When state held above a dialog or popover must start fresh on each open, reset it at the open call site. When: Dialogs, popovers, sheets or drawers whose content must start fresh each time they open.
- `server-auth-actions` [critical] Check the caller's identity and permissions inside each server function or in middleware attached to it. Do not rely on page, layout or route guards. When: Server functions that the client can call, such as React Server Actions or TanStack Start server functions, especially ones that read or change data.
- `server-cache-react` [medium] Wrap repeated server-side work such as auth and database reads in `React.cache`, and call it with primitive arguments so calls hit the cache. When: React Server Components that call the same non-`fetch` async function, such as a database query or auth check, from several components in one render.
- `server-components-data-exposure` [high] In a Server Component, load data already shaped for display and without sensitive fields. Do not pass raw records as props, because a Client Component child serializes them to the browser. When: React Server Components that load records and pass them as props to other components.
- `server-dedup-props` [low] Pass the data once from a Server Component to a Client Component. Sort, filter or pick fields in the Client Component, so the same data is not serialized twice. When: React Server Components that pass props to Client Components and send both a value and a copy derived from it.
- `server-no-shared-module-state` [high] Pass request-scoped data through props, arguments or request context. Do not write it to mutable module variables in code that renders on the server. When: Code that renders on the server, such as Server Components and components rendered during SSR, that writes to module-level variables.
- `server-parallel-fetching` [medium] Do not await data in a parent that renders children which fetch their own data. Move each fetch into its own component and compose them. When: React Server Components where a parent awaits data before rendering child Server Components that fetch independent data.
- `server-serialization` [medium] Do not pass a whole record from a Server Component to a Client Component. Pass the fields the client reads, because all passed data is serialized into the response. When: React Server Components that pass objects with many fields as props to Client Components that use only a few of them.
